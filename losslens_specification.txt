Glossary
T erm Meaning
Bookmaker A company that accepts bets and sets the odds.
Stake The money a person puts on one bet.
Returned (amount
returned)
The money paid back to the person after a bet, including the stake if
they won. A lost bet returns 0.
Net result Returned minus stake. Negative means a loss.
Turnover The total of all stakes over a period. A person who deposits KES
1,000 and re-bets winnings can have a turnover far above KES 1,000.
Decimal odds The total returned per KES 1 staked if the bet wins. Odds of 2.10
mean a KES 100 winning stake returns KES 210.
Market One question a bookmaker takes bets on, such as who wins this
match, with an odd for each possible answer.
Three-way market A market with three outcomes, for example home win, draw, away
win.
Two-way market A market with two outcomes, for example over or under 2.5 goals.
Book total ( B) The sum of 1/odds over all outcomes of one market. A fair market
has B = 1. Bookmakers set B above 1.
Overround or margin
( m)
B − 1. It is the bookmaker's built-in edge, expressed as a fraction.
Expected return
factor ( f )
The average amount returned per KES 1 staked for a bettor with no
edge. For one bet, f = 1/B = 1/(1 +m).
Expected loss Stake times (1 − f ). An average, not a prediction for any one bet.
Leg One selection inside a multibet.
Multibet
(accumulator)
One bet that combines several legs. It wins only if every leg wins.
The odds are the product of the leg odds.
Cash-out Settling a bet early for an amount the bookmaker oers, before the
result is known.
Void bet A bet cancelled and refunded. It carried no risk, so it is excluded
from calculations.
Lookup table A table of typical margins by bookmaker, built from odds the team
collects. Used when the user does not enter a full market.
Exact mode Entering every outcome's odds for one bet so its margin is computed

Review screen The screen where the user checks and corrects imported or typed

1 Background and Goal
1.1 The problem in plain language
Many people who bet on sports in Kenya do not know how much betting is expected to cost them.
They see single results: a win on Saturday, a loss on Sunday. They rarely see the long-run average
cost built into the odds.
That cost exists because bookmakers do not oer fair odds. Here is the idea with the smallest
possible example.
A fair coin toss. A fair bookmaker would oer 2.00 on heads and 2.00 on tails. Then 12.00 + 12.00 =
1, so B = 1 and the bettor gets back, on average, exactly what they stake.
A real bookmaker. Suppose the bookmaker oers 1.90 on each side. Then
B = 11.90 + 11.90 = 1.0526, m = 0.0526, f = 11.0526 = 0.95.
On average, every KES 100 staked comes back as KES 95. The KES 5 dierence is the bookmaker's
expected prot, and it is the bettor's expected loss.
Multibets multiply the eect. For a bet with k legs, each with the same margin, the factor is
f k. With f = 0.95 and four legs the factor is 0.954 = 0.8145. Each KES 100 staked comes back
as about KES 81 on average. (The gure 0.95 is the example above, not a measured bookmaker
margin.)
1.2 The goal
Build a small, private, mobile-friendly tool that:
1. takes a person's own betting history with as little eort as possible,
2. shows what that betting is expected to cost, next to what they actually lost,
3. shows why a few wins or losses say little about the long run, and
4. gives them a next step: set a weekly limit, wait out an urge, or talk to someone.
1.3 Why the numbers matter to the people judging it
The product will be presented to people who work with expected value, variance and pricing.
They will ask where every gure comes from. The tool is built so that every gure has a stated
method, a stated sample, and an accuracy label.

2.2 The decision it changes
Should this person set a betting limit, wait and talk to someone, or stop? The tool changes
the decision by replacing a vague feeling with a number in shillings, shown as a range, with the
method visible.
2.3 The two parts and how they t
 T rue Cost (the core): data input, margin estimate, expected loss, projection, simulation,
weekly limit.
 Precious (the support): urge timer, resources, Talk to someone, protected report. Each
supporting feature either feeds the number or responds to it. A feature that does neither is
not in version 1.
2.4 Design principles
1. Honest numbers. Every gure is an estimate with a range and a source. Nothing is shown
with more precision than it has.
2. Low eort. Typing every bet is the biggest reason people stop using trackers. Import rst,
review second, type last.
3. Private by default. All data stays on the device.
4. No harm. The app never encourages betting, never rewards betting streaks, and shows
help before anything else when someone says they cannot stop.
5. No overclaiming. The app does not claim to treat, diagnose, cure or reduce gambling.
2.5 Non-goals for version 1
Not built, and not to be added without a written decision:
 accounts, logins or any server that stores user data;
 an AI chat assistant;
 peer support rooms, matching, events or video features;
 CBT lessons;
 risk scores or relapse prediction;
 M-Pesa monitoring or any reading of SMS or notications;
 connecting to a bookmaker's account;
 booking or payment for therapy inside the app;
 any insurance product (Section 17).

A.1 truecost.js
// truecost.js -- reference implementation of the True Cost calculations
// All money values are in KES. Odds are decimal odds (e.g. 2.10).
function bookTotal(odds) {
if (!Array.isArray(odds) || odds.length < 2) throw new Error("need >= 2 odds");
let b = 0;
for (const o of odds) {
if (!(o > 1)) throw new Error("odds must be > 1");
b += 1 / o;
}
return b; // B
}
function overround(odds) { return bookTotal(odds) - 1; } // m = B - 1
// Expected return per KES 1 staked, no edge, one bet
function factorFromMargin(m, legs) {
if (!(m >= 0)) throw new Error("margin must be >= 0");
if (!Number.isInteger(legs) || legs < 1) throw new Error("legs must be integer >= 1");
return Math.pow(1 / (1 + m), legs); // f
}
function factorExact(odds) { return 1 / bookTotal(odds); } // full market
function expectedLoss(stake, f) { return stake * (1 - f); }
function actualNet(stake, returned) { return returned - stake; }
// Expected-loss range from low/high margins (e.g. 25th and 75th percentile)
function expectedLossRange(stake, mLow, mHigh, legs) {
return {
low: expectedLoss(stake, factorFromMargin(mLow, legs)),
high: expectedLoss(stake, factorFromMargin(mHigh, legs)),
};
}
// Win probability that yields expected return factor f at odds O
function winProbability(f, O) {
const p = f / O;
if (p > 1) throw new Error("inconsistent inputs: p > 1");
return p;
}

// Share of simulated flat-stake bettors with total return > total staked
function simulateAhead(p, O, checkpoints, runs, seed) {
const rand = mulberry32(seed);
const maxN = Math.max(...checkpoints);
const ahead = checkpoints.map(() => 0);
for (let r = 0; r < runs; r++) {
let wins = 0;
for (let n = 1; n <= maxN; n++) {
if (rand() < p) wins++; // one draw per bet, in order
const idx = checkpoints.indexOf(n);
if (idx !== -1 && wins * O > n) ahead[idx]++; // stake 1 per bet
}
}
return checkpoints.map((n, i) => ({ bets: n, shareAhead: ahead[i] / runs }));
}
